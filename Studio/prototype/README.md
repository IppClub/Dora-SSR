# Dora Studio 可点击原型 v0.6

这是用于评审产品流程、视觉方向和页面状态的独立交互原型，不是正式 Studio 应用。v0.3 对齐现有 Dora Web IDE 的深灰与金黄主题、细分隔线、紧凑工具栏及 Agent 输入区；替代 v0.2 的浅色紫调。试玩为主区域，Agent 为右侧栏，移动端单面板切换；日志与状态演练默认收起。没有新建 workspace、迁移 Agent 或接入 Dora Web 引擎。

视觉依据：Tools/dora-dora/src/Theme.ts、Frame.tsx 和 AgentComposer.tsx；当前标识 dora-symbol.svg 复制自 Docs/static/img/site/logo.svg，采用不带底部文字的图形版本。原型独立 CSS 映射现有主题值，不修改原 Web IDE。

## 打开

直接打开 `index.html`，或在仓库根启动静态服务：

```sh
python3 -m http.server 8897 --bind 127.0.0.1 --directory Studio/prototype
```

访问 `http://127.0.0.1:8897`。评审结束停止服务。

## 可评审流程

v0.6：个人 API 主要展示已消耗用量，不再以“余额未知”为主信息。概览提供调用次数、已记录输入/输出 Token；用量记录包含调用时间、项目、模型与是否缺失 usage，和平台费用分开。无明确单价不展示估算金额。当前仍只有会话内模拟数据。

v0.5：模型页以人民币创作额度为主，突出当前模型实际可用金额，并分别展示平台余额、实际使用和预留。首页/Agent 同步显示金额；单价与并发收进详情。BYOK 显示服务商余额未知、费用另计。替代旧点数界面，不新增充值或提现。

v0.4 体验改进：新建并生成、首次运行空态、手机自动进入 Agent、主动暂停/排队退出、独立会话项目与重命名、已运行版本发布保护、已发布快照 Remix。对话在侧栏内滚动。详见 [产品体验评审](../docs/DEMO_REVIEW.md)。

- 首页：一句描述创作、空白新建、上传 `.dora`/ZIP、粘贴项目链接。
- 工作室：试玩主区域与右侧 Agent 组成统一工作台，代码/资源切换、草稿与运行快照分离、检查点恢复；手机切换试玩/Agent。
- 自动创作：示意阶段自动推进，不逐补丁确认；用顶部连接按钮演练暂停与续接。
- 异常：展开工作室底部“设计评审 · 状态演练”，测试排队、额度不足、编译失败、不兼容、缺失 usage。
- 模型：共享配置/个人 API 选择、剩余可用金额、三级并发、演示授权撤销。
- 分享：人工发布、默认源码私有、人工开放允许 Remix；私有作品访客 clone 被拒绝。
- 管理：共享配置/费率/并发、账号总及逐 API 授权、缺失 usage 暂挂人工处理。
- 示意游戏：点击画面后方向键移动，或使用画面下方按钮收集星光。

## 模拟与安全边界

全部状态在当前页面内存，刷新后重置。包上传只读取文件名，不读取内容；链接不会下载；不发起模型调用，不接收/保存真实 API Key，不连接云服务，也不修改作者项目源码。示意游戏是 Canvas 交互，不是 Dora runtime，不用于证明引擎/Agent 能力迁移。

费率、金额、预留、请求及结果均为示例，不是供应商真实报价。默认账号余额 ¥120、共享授权余额 ¥80，当前模型可用 ¥80。默认人民币单价为输入 ¥1/百万 Token、输出 ¥3/百万 Token；一次演示按输入 20 万/最大输出 20 万预留 ¥0.80，按示例实际输入 10 万/输出 8 万结算 ¥0.34。更改后台单价影响后续预留与结算，不改历史账单。两个平台模型选项在此原型中共用这一演示配置及授权额度，不代表已实现多配置独立账本。余额使用整数分；真实服务仍需更高精度定点账务及真实 usage 适配。

BYOK 不扣平台额度，以输入/输出 Token 与调用次数记录消耗；默认每次演示返回输入 100,000、输出 80,000 Token。缺失 usage 的请求单独标为待补记，计入调用次数、不计入已知 Token 合计；暂停恢复不重复记一次调用。无个人 API 单价时不估算金额；不会读取供应商账单或统计 Studio 之外的用量。平台待核调用需要填写原因后释放，BYOK 缺失用量不冻结平台余额。生产加密、账务原子性、SSRF、解包、权限、供应商能力和完整 Agent 工具仍需正式实现与验收。

原型管理员入口用于评审，不是生产权限控制。所有发布链接使用 `example.invalid`。现有 Agent 全能力仍是首版要求，原型中的四个阶段只是界面载体，不重定义 Agent 决策和工具执行顺序。

## 自动化检查

静态服务运行后，使用已安装 Playwright 的 Node 环境：

```sh
node Studio/prototype/test.cjs
node Studio/prototype/money-test.cjs
```

若 Playwright 不在默认模块搜索路径，可设置 `STUDIO_PLAYWRIGHT_MODULE` 为其绝对模块路径；缺少 bundled 浏览器时用 `STUDIO_CHROME_PATH` 指定已安装 Chrome 可执行文件；`STUDIO_PROTOTYPE_URL` 可覆盖本地服务地址。截图写入忽略目录 `artifacts/`。检查覆盖核心交互、错误状态和 1024/736/390/320 宽度页面溢出，不代替真实移动设备或 Dora 引擎验证。

## 评审重点

优先确认 Agent 与试玩的空间分配、代码入口是否足够直接、暂停/错误是否可理解、共享模型额度是否清晰，以及发布和源码开放是否容易区分。颜色与字体为临时视觉，不构成最终品牌方案。
