# 模型账本 SQLite 适配器

> 2026-09-19：当前实现已迁移至 Go 的 `internal/studio`；本文中的 `.mjs` 模块名是迁移前的设计来源，不是现行部署入口。

`model-ledger-sqlite.mjs` 是可信服务内部接口，不是 HTTP API。使用 Node 内置 `node:sqlite`，当前在 Node 24.19.0 验证。金额沿用整数 nano-CNY，费率随请求固定；不把 BYOK 计入平台共享额度，本适配器当前只实现共享额度路径。

## 部署边界

适用于同一主机、同一本地磁盘数据库文件上的多个服务进程。WAL、FULL 同步和 BEGIN IMMEDIATE 事务串行化写入。禁止把数据库放在网络共享目录，也不支持多台主机分别持有独立账本却共享同一个 API 并发预算。SQLite 是首个可替换存储适配器，不锁定最终云数据库供应方；多节点部署需要共享关系数据库适配器。

## 接入约束

- normalizeModelUsage 只规范化可信适配器已解析的非负 bigint 计数，不是供应商解析器。收据保留已提供的缓存/推理/音频等明细，不把重叠计数相加；未提供字段保持未知。inputTokens/outputTokens 的计费含义必须在接入具体协议时明确，尤其不能默认缓存总被包含或总被排除。当前平台仍按管理员输入/输出两档费率计量，未实现供应商差异费率或非 Token 单位账本。

- configure 只允许受信任的管理员服务调用，第四参数必须提供从已验证身份取得的 actorId。修改上限时保留已有消费、预留和在途计数，授权绑定不可更换。管理员鉴权尚未实现，不能直接暴露此接口。
- configure、reserve 和 transition 在同一事务追加审计；调额记录操作者及修改前后值，请求记录状态/版本和金额但不复制输入正文或 fingerprint。重放 reserve 不重复记事件。audit 为受限分页内部读取接口，尚无管理员查询页面或防篡改外部归档；持有数据库写权限者仍可能修改记录。
- reserve 的身份、额度预估和费率必须由后端配置及授权计算，不能采用客户端自行提交的数值。fingerprint 必须覆盖规范化模型输入、模型及配置版本，且不得含密钥。相同请求 ID/绑定返回已有状态；不同绑定拒绝。
- 只有 transition 的 dispatch 成功提交者才能发起供应商请求。必须使用持久记录的 expectedVersion；旧版本转换拒绝。重放 reserve 返回 in-flight 不授权重新派发。
- 并发饱和时 reserve 持久化 queued 意图，不占金额或槽位；其 ID 仍固定绑定平台资金来源。admitQueued 在事务内重新检查授权/金额/三级槽位，成功才预留，仍拥堵保持排队，失去资格转为拒绝终态。cancel 支持取消排队且不释放其他请求的预留。`model-queue-coordinator.mjs` 为仍在线的 Agent 请求提供进程内自动等待与派发：按进入顺序检查，但会跳过仍受账号/授权限制的队首，避免阻塞其他可获准账号；每账号最多等待 3 个请求、单进程最多等待 256 个请求，默认等待 4 分钟，并在断线、停止、超时或服务关闭时取消未派发记录。请求正文、发送闭包与密钥均不持久化。
- dispatch 在事务内再次检查当前授权和限额。scope 检查抛错时保留 reserved；调度器必须后续取消或重新调度，不能遗忘其槽位。下述目录拒绝则会提交释放预留的终态，两种结果不能混淆。
- finish 与计数/金额在同一事务提交；缺 usage 释放并发、保留金额暂挂。以后核对 usage 可再次 finish，但不会重复释放并发。终态或旧版本不能再次结算。
- 派发标记提交后、网络调用前崩溃仍属于不确定窗口。重启不得自动退款或重发；供应商请求标识、恢复扫描和核对作业尚未实现。
- request/scope 是内部读取接口，不提供租户鉴权。对外路由必须先验证归属，不能用“知道请求 ID”代替授权。

## 已验证 / 未验证

### 共享目录版本绑定

可信调用者向 reserve 提供 configurationVersion 时，版本进入持久化幂等绑定。首次预留、admitQueued 和 dispatch 均在账本连接的 BEGIN IMMEDIATE 事务内读取 model_configurations，要求 apiId 对应 platform 所有的 shared 行，且 enabled=true、version 相同。目录必须与账本使用同一本地数据库；缺表属于部署错误并回滚，不能跳过检查。目录缺失、停用或版本改变拒绝请求，不自动采用新配置。

最终 dispatch 的目录检查失败时，原 reserved 请求释放金额/并发并记录 rejected-before-dispatch；执行器返回 denied 而不调用 transport。已提交 in-flight 的请求不被后续目录停用追溯取消或退款，仍须按实际终态结算。这里的线性化边界是派发标记提交，不承诺取消已经获准的网络操作。

不传 configurationVersion 的历史内部调用保留原行为。正式模型网关必须由服务端解析并强制绑定该版本，不能接受客户端省略；此入口尚未实现。密钥版本和供应商请求内容还需与选定配置协调。专项测试覆盖目录启用结算、缺失/停用拒绝、排队版本变更、预留后另一连接停用与占用释放；不是生产网关或供应商验证。

生产派发连接应使用 `openModelLedger(path, {requireConfigurationVersion:true})`。严格模式拒绝没有版本的新准入及历史排队请求；没有版本的历史 reserved 请求在 dispatch 时释放占用并拒绝，已有 in-flight 收据与结算不受影响。默认 false 仅保留旧内部调用兼容。此选项为连接级部署策略，不是数据库持久化策略：所有有派发权限的进程必须一致启用，混用宽松连接仍可绕过。实际网关启动装配与统一策略检查仍待实现。

BYOK 使用独立 byok_requests 表，beginByok 登记由可信网关绑定的请求 ID/账号/项目/配置/模型；它只是用量日志，不授权派发，也不提供并发控制。初始 usage=null 表示待补记，不能算作零用量；recordByokUsage 以版本检查写入一次规范化计数，并与审计原子提交。分页读取绑定账号，不返回 fingerprint 或供应商余额。重复登记/补记不改变平台金额与槽位。未接 BYOK 密钥管理、实际网关派发或用户汇总页面；登记本身不能证明网络请求已到达供应商，界面统计需区分登记状态与实际调用证据。

GET /api/byok/usage 提供身份绑定的有界明细页和账号汇总，在同一 WAL 读取快照中计算。registeredRequests 表示已登记请求，并非已完成调用；knownUsageRequests/pendingUsageRequests 分开，inputTokens/outputTokens 只累计已知计数，不把缓存/推理明细再次相加。所有计数作为十进制字符串返回，避免精度损失。摘要目前以游标遍历该账号记录计算，内存有界但时间为线性；大规模部署前需事务维护的增量汇总与压测。认证仍需平台实现；用户用量 UI 尚未接入。

`model-allowance-route.mjs` 提供 GET /api/model-grants/:id/allowance 读取边界，账号只来自注入的可信 authenticate 结果，外部授权与不存在授权统一 404；禁止缓存。ledger.allowance 在一个一致事务快照里核对归属并读取两层金额，返回精确 nano-CNY 字符串；主可用量取两层未占用额度较小值，不叠加。停用/零容量返回不可用而非伪造零余额，并发饱和与金额不足分别标记。响应不包含共享密钥、供应商地址、其他用户记录或 API 全局在途计数。它是展示快照，不是下一次调用的准入凭证；实际请求仍需原子预留。认证实现、服务挂载和正式金额 UI 尚未接入，当前 HTTP 测试使用 fixture 身份。

`model-request-executor.mjs` 把可信调用意图接到 reserve → dispatch → provider adapter → finish；重复请求只返回已有状态，不再次调用 transport。适配器只有在确认供应商任务结束后才能返回 completed:true；usage 必须规范化为整数，否则按不确定请求处理。连接异常不等于模型停止，保留金额和并发等待核对。确认结束但没有 usage 时释放并发、保留金额。客户端断开不阻止已确认结果结算。

内部 resumeQueued:true 允许显式恢复已登记 queued 请求，先验证原绑定，再通过 admitQueued 取得槽位，随后复用相同派发/收据/结算流程。默认重试不恢复队列，reserved/in-flight/终态也不重新派发。Agent 模型路由持有当前在线请求并委托同一协调器恢复；每次恢复都重新检查账号、授权、金额、目录版本、密钥版本和三级并发，排队期间不持有解密后的密钥。协调器在任务结算后立即唤醒，也用短周期轮询覆盖其他进程释放槽位的情况。服务重启不恢复正文或自动重发：旧 HTTP 请求会失败；若仍获授权的在线 Agent 以相同请求 ID 和完全相同指纹重新提交，新的协调器可接管该 queued 记录，否则它保持不占槽位/金额的历史记录。这是避免在无法证明用户任务仍在线时重放提示词的安全边界，长期无人接管记录的周期清理仍待接入。

该执行器不是公开网关：未提供供应商协议/SSE 解析、密钥与配置解析、鉴权、持久响应或自动核对。本机 HTTP fixture 已覆盖派发先提交、一次结算与重复请求不重发。

确认终态后，执行器先用 receipt 转换持久化规范化 usage（或明确的 null），再用 finish 结算。收据只接受一次，并与审计一起提交；结算不能覆盖已有收据用量。结算存储失败会抛错并保留在途记录和收据，内部 settleRecordedModelRequest 可在重开后完成结算，不访问模型。缺 usage 的收据结算为 pending-usage 后仍允许后续核对实际用量。尚未实现自动扫描调度；收据首次写入失败或响应尚未写入就崩溃仍需供应商侧核对。收据不含响应正文，不能据此恢复完整 Agent 回复。

真实临时 SQLite 文件测试覆盖关闭重开、独立连接、8 个子进程争用单槽位、双进程派发版本竞争，以及请求记录写入失败后全部金额/槽位事务回滚。测试只清理自己的临时目录。

审计专项验证重开、游标分页、幂等重放不重复记录，以及审计写入故障时调额/结算一起回滚。

`model-recovery.mjs` 提供有界内部收据恢复批次，通过 SQLite 部分索引仅选取 in-flight 且已有收据的记录，按请求 ID 游标推进。单行错误报告 retry-required，不阻挡其余行；版本竞争后读取已结算/暂挂状态才报告 already-processed。每轮完整扫描必须从空游标重启，才能重试失败记录及发现游标后方新增收据。尚未接服务启动/周期调度、退避与告警，不应忙循环调用。没有收据的不确定调用不自动释放、不重发。

尚未验证断电、强制杀进程、磁盘故障、备份恢复和生产负载；未接真实模型供应商、BYOK、管理后台或正式 Agent。现有 JSON 行存储为内部初版，正式部署前还需迁移版本管理、审计查询授权/归档与恢复索引。
