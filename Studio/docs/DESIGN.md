# Dora Studio 产品与技术设计方案

“AI 自动试玩”指原 Dora Agent 按既有决策流程调用构建、命令/预览工具来触发，不授权 Studio 在文件回写或任务终态另起自动编译与运行。Studio 仅保存作者结果与展示工具反馈；用户主动编译/试玩入口保留。

更新日期：2026-09-16。状态：设计基线已确定，分阶段开发中；实际完成度以进度表为准。

本文整理产品形态、工程路线与目录结构的共识。工程状态及验证证据以 [开发进度跟踪表](PROGRESS.md) 为准。初始源码分析基线为 Dora-SSR `680c4dd46`，不能当作当前代码版本或验证结果。

为尽快形成真实可用闭环，当前先交付 [受邀预览 MVP](MVP.md)：一种真实共享模型、首轮生成、可持续继续描述修改、刷新/失败恢复及单环境 HTTPS 验收。产品不限制继续修改轮次，MVP 仅以至少两次连续修改作为验收样本。MVP 是进入受邀 Beta 的阶段门，不替代本文定义的完整首版；BYOK 派发、完整 Agent 对照、发布/Remix、外部 clone 和浏览器/设备矩阵仍保留在首版范围。

界面流程已建立 [可点击低保真原型](../prototype/README.md)，用于评审首页、工作室、模型、分享及管理后台。其 Canvas 游戏与调用状态都是模拟，不代表真实 Agent 或 Web 引擎验证；原型检查另记在进度表。

## 1. 产品定义与边界

Dora Studio 是浏览器游戏工作室：打开链接即可创作，修改后在浏览器试玩，发布后通过链接分享作品。

首版是 **AI 创作＋代码可编辑** 的产品，不是先交付在线 IDE 再附加 AI。以一句描述生成游戏为主入口，AI 直接修改并自动试玩；以现有 Dora Agent 的完整能力与行为为迁移基线，不另行设计简化 Agent 或新的自动试玩成功标准。

首个可用服务面向受邀用户的小规模部署，按真实多用户架构建设，不以完整公共社区或自部署平台为首个交付目标。受邀作者发布的游戏可供公众通过链接试玩。

| 能力 | 浏览器 | 云端 |
| --- | --- | --- |
| 编辑 | 编辑器、文件树、本地工作区、搜索、资源预览 | 项目元数据、授权与同步 |
| 编译 | Lua 检查、TS/TSTL，以及完整 Agent 所需的工具适配 | 可选耗时编译与资源转换作业，不借此运行渲染游戏 |
| 试玩 | 游戏逻辑、物理、渲染、输入、音频、存档 | 不启动产品试玩会话，不传输游戏渲染视频流 |
| Agent | 自动应用修改、编译、试玩及现有工具反馈 | 完整现有 Agent 迁移、会话与检查点、模型调用与平台流控 |
| 发布 | 选择快照、兼容性检查 | 产物校验、不可变版本、对象存储与 CDN |

纯 Web 指不依赖用户本机原生 Dora 服务，也不依赖云端游戏渲染进程。它不禁止后端执行受限、短生命周期的编译或资源转换工具。

原生 Dora 继续承担重型开发与原生目标能力；两种产品共享脚本 API、项目与资源规范，不互相替代。

### 1.1 目标用户

| 用户 | 需求 | 首要入口 |
| --- | --- | --- |
| 学习者 | 从可玩例子理解代码，免安装 | 模板、教程、复制修改 |
| 独立开发者 | 快速验证玩法，跨设备测试 | 工作室、资源、分享 |
| AI 创作者 | 从描述得到原型，再迭代调整 | Agent 与预览 |
| 教师与活动组织者 | 降低部署成本，收集作品 | 模板链接、项目复制、作品页 |

### 1.2 首版范围与非目标

首版聚焦轻量 2D，以 Lua 与 TypeScript/TSX 建立基础闭环，交付完整现有 Agent、本地创作、云保存、共享 API 管理、自带 Key、快照发布及手机试玩。创作入口同时包含空白新建、一句描述生成、`.dora`/ZIP 上传、外部项目链接和 Studio 开源作品链接复制。

首版资源来源为内置素材、用户上传，以及当前 Dora Agent 已支持的音乐/音效生成链路。不新增 AI 图片、视频或另一套音频生成服务。既有生成实现的平台依赖需要迁移，但不得因适配困难静默删除能力。

不以完整 3D 制作、任意原生插件、完整 Git 工作流、实时多人协同、大型资源管线、公共社区、所有原生项目无修改兼容为首版目标。外部 Git clone 明确属于首版，不等于承诺 commit/push/同步上游。新语言界面与额外兼容层按需求扩展；完整现有 Agent 依赖的编译、文档与工具能力不能以“更多语言后置”为理由删减。

匿名访问用于公开作品试玩。早期关于匿名编辑模板的建议不再作为首版必交付要求；创作、API 使用与云项目访问按受邀账号授权。

## 2. 用户设计

### 2.1 信息架构

- 创作入口：一句描述、新建、上传项目、粘贴项目/作品链接；模板为辅助入口，完整探索社区后置。
- 项目：同一项目列表；不向用户区分“本地项目”和“云项目”。打开项目时先完成必要的上传或下载，并用阻塞式进度条明确等待状态；同步完成后才进入可编辑、可连接 Agent 的工作区。只有其他设备上的内容更新时间更晚时，才询问使用较新内容还是保留当前内容。
- 工作室：代码、资源、Agent、试玩、问题与日志。
- 作品页：独立试玩、说明、反馈，以及作者允许的 Remix 入口。
- 账号模型设置：获授权的共享 API、人民币计价费率、额度/并发、排队状态与自带 Key。
- 管理后台：受邀账号、共享 API 配置、账号及逐 API 授权、金额调整与结算审计。

### 2.1.1 受邀账号与登录

首版采用“邀请码＋账号密码”。首位管理员由仅限空账号库的受信命令生成一次性管理员邀请码；其后管理员在账号后台生成普通创作者或管理员邀请码，并通过可信渠道交付。邀请码只展示一次、默认 7 天到期、核销后不能复用。用户设置独立账号名和至少 12 字符密码，注册成功即建立会话；以后凭账号密码登录。账号停用拒绝新登录和云端接口，退出只撤销当前设备会话，本机草稿保留。

身份边界由同源 HTTPS 服务承担：服务端保存加盐密码派生值及邀请码摘要，不保存明文；登录路由拒绝非 TLS 连接，随机会话令牌只通过 Secure、HttpOnly、SameSite=Lax、Path=/ 且无 Domain 的 `__Host-` Cookie 下发。前端只读取 `/api/session` 的账号投影，不保存密码、邀请码或令牌；项目、模型与管理接口仍逐请求重新鉴权。匿名可编辑本机草稿，但创作云端同步与模型用量须登录。登录入口与后台邀请已接入正式前端；生产防滥用/邮件找回等运维边界仍需验收，不因本地联调通过宣布完整账号服务已交付。

桌面工作室采用统一工作台：游戏试玩占主区域，Agent 是试玩界面的右侧栏，避免两个等权卡片并排。代码和资源在主区域切换，问题/运行日志默认折叠；顶部保留项目状态、修改记录与发布。首页突出一句描述生成，上传、新建和链接 Remix 为次级入口。移动端以“试玩与编辑 / Dora Agent”切换单面板，避免长页面上下堆叠。v0.3 取代浅色紫调方案，直接对齐 Dora Web IDE 的设计语言：依据 Tools/dora-dora/src/Theme.ts 使用 #161616 底层、#1d1d1d 工作区、#242424 抬升表面、#fac03d 强调色和 #ffffff20 分隔线；参考 Frame.tsx 的紧凑工具栏与 AgentComposer.tsx 的深色输入框、金色发送按钮。使用现有 Dora 官方标识，工作区采用连续分栏而非悬浮卡片。技术与模拟说明集中到评审入口，不挤占创作主流程。视觉方案仍待用户评审，不代表正式前端已实现。

### 2.2 核心旅程

v0.4 原型体验约定：首页操作明确为“新建并生成”，为独立项目创建首轮请求；生成前展示无快照空态，移动端进入 Agent 查看进度，完成后提供试玩入口。对话区域独立滚动，支持主动暂停和排队退出，失败不丢弃用户输入。项目可命名和切换；发布仅允许成功运行且与草稿一致的快照，Remix 复制已发布源码而非未发布修改。原型仅在本次页面会话保留这些数据，刷新清空；正式持久化仍按后续技术方案实现。详见 [产品体验评审](DEMO_REVIEW.md)。

| 旅程 | 流程 | 必须保持的规则 |
| --- | --- | --- |
| AI 创作（主入口） | 一句描述 → 按现有 Agent 流程自动修改/编译/试玩 → 查看结果并继续描述 | 不逐次等待修改确认，不改现有 Agent 的模式、工具及完成标准 |
| 新建/上传 | 新建空白项目或上传 `.dora`/ZIP → 编辑/描述修改 → 运行 | 与描述生成并存；导入成功与 Web 可试玩分别检查 |
| 链接 clone/Remix | 粘贴外部开源 Git/ZIP 或 Studio 分享链接 → 识别/校验 → 复制为独立项目 → AI 修改 | 外部不限 Git 托管商；Studio 源码需人工开放并允许 Remix |
| 发布分享 | 人工发布固定版本 → 分享链接 → 公众试玩 | 源码默认私有，公开试玩不授予 clone 权限 |

修改前自动建立可恢复检查点，差异可查看且代码可手动编辑；不增加每次补丁的确认门槛。发布作品、开放源码/允许 Remix、删除项目仍由用户主动操作。现有 Agent 内部计划、问题询问及权限语义不被“自动修改”改写。

### 2.3 状态与恢复

- 运行绑定不可变项目快照；界面只显示更新时间和“有未运行修改”，不向用户暴露 revision/version 编号。
- 本地运行不要求先上传云端；断网时可编辑和运行已缓存的项目与依赖，但不继续云端 Agent 任务。
- 前端工作区是作者内容的权威来源；保存后自动同步到远端和 Agent，正常状态不提供手动上传、比较或接收按钮。只有网络/同步失败时提供重试。
- 登录后打开已启用 Agent 的项目会自动建立专用 Agent 连接并同步当前工作区；不提供日常“连接 Agent”按钮。授权、宿主或网络失败后才显示“重试连接”。空白项目仍在用户首次提交 Agent 描述时启动会话，避免无意产生模型任务。
- Agent 一旦连接即可随时接收新的用户描述，不以“首轮完成”“上一轮回写完成”、任务终态或未保存编辑作为输入框准入条件。若工作区有编辑，发送前自动保存并同步给 Agent；每条描述使用独立请求标识持久化和投递，文件回写与云同步在后台继续，短暂的实际发送事务仍防止重复点击。
- 用户登录或重新打开项目时，若远端更新时间晚于本机，才提示“保留本机 / 使用远端”。使用远端前先把本机内容写入历史记录；其余情况不要求用户处理同步。
- 编译失败可保留旧预览，但明确标记旧版本。诊断尽可能回到原始 TS/Yue 文件。
- 首版可靠重新运行，不默认承诺任意脚本热更新。
- 导入、clone 与新建默认形成独立项目；同步冲突不得静默覆盖。
- 编辑、草稿预览、正式作品存档分开；卡死恢复不丢失工作区。
- 浏览器可执行资源不等于源码保密，不承诺无法提取发布内容。
- 页面关闭或连接失效后保存 Agent 检查点并暂停，重新打开后可继续。不继续无人观察的代码生成，不把恢复实现为重新发起整个任务。
- 已发出且无法立即取消的请求需尽力终止并保留调用账务，防止迟到结果作用于错误快照；不得以断线释放全部已消耗金额。

## 4. 工程决策

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 产品位置 | 仓库顶层 `Studio/` | 独立产品，不是辅助工具 |
| 仓库 | 同仓起步，暂不拆仓 | 原子迁移共享代码、降低跨仓协调成本 |
| 前端 | 新入口，保留旧 IDE | 不在 App.tsx 堆积 cloud/native 条件分支 |
| 后端 | 独立 TypeScript/Node.js 模块化服务 | 云平台不依赖引擎帧循环和全局状态 |
| 复用 | 抽取共享能力与契约，平台各自适配 | 避免应用整体复制，也避免过度统一 |
| 引擎 | 完善浏览器运行 SDK，不新增云平台宿主模式 | 引擎负责运行，不承担账号和租户 |
| 构建部署 | Studio 独立 workspace、锁文件、构建与发布 | 不改变旧 IDE Assets/www 打包生命周期 |
| 实施范围 | 分阶段迁移，先编译与本地运行 | 不同步开展全量重写和语言版本升级 |
| 产品优先级 | AI 创作为主、受邀服务首发 | Agent 完整迁移、API 后台与 clone/Remix 纳入首版 |
| 自动化边界 | AI 直接修改并自动试玩，平台发布权限独立 | 保持现有 Agent 语义，修改可撤销，对外开放由用户决定 |

### 4.1 拟定目录

以下是目标结构；当前已建立文档、独立交互原型、workspace、contracts 与 compiler 基础，其余按阶段需要落地。`Studio/prototype` 不作为正式应用架构或共享包实现。当前实现与测试证据见 [工程说明](DEVELOPMENT.md)，不由目录存在推定功能完成。

| 路径 | 职责 |
| --- | --- |
| `Studio/apps/web` | React/Vite 前端、AI 主入口、账号项目页、工作室与管理后台界面 |
| `Studio/apps/server` | 云 API、完整 Agent 适配、共享模型池、流控/结算与后台作业，初期同工程 |
| `Studio/packages/contracts` | 项目、编译、运行、Agent 的协议与版本 |
| `Studio/packages/compiler` | 平台无关 TS/TSTL 编译核心 |
| `Studio/packages/tstl` | 整体迁移的 Dora TSTL vendor、许可证及浏览器适配；显式源码包导出，由两入口打包，不复制维护 |
| `Studio/packages/compiler-web` | 浏览器编译 Worker、生命周期客户端及静态产物构建；复用 compiler/tstl/contracts |
| `Studio/packages/editor` | 可复用编辑器集成与组件 |
| `Studio/packages/runtime-web` | 浏览器 RuntimeHost，消费引擎 Web 产物 |
| `Studio/docs` | 设计、进度、开发部署与验证资料 |

现有 `Tools/dora-dora` 保持路径与构建入口，逐步通过显式本地包依赖消费共享模块；不得直接跨目录引用应用内部源码。共享包独立构建为 JS/声明产物或明确约定的包导出；具体接入方式由工程基线阶段验证。

引擎 C++、绑定、Emscripten 平台仍在 `Source/`、`Projects/Web/`。不复制引擎源码或提交一份 Studio 私有 runtime 分叉。

### 4.2 依赖与复用约束

- 应用/适配器依赖共享包；共享包禁止反向依赖任何应用。
- 编译核心不依赖 React、Monaco、DOM、Service、原生 HTTP 或引擎服务。
- 共享协议不引入服务器 SDK 或平台密钥。
- 相同规则共享，不同生命周期分开；本地文件写入与云 revision 提交不强行统一完整流程。
- 不抽取没有实际消费者的通用框架；采用逐切片迁移，不先搬整个 App/Service。
- 抽取后让旧实现消费新核心并删除重复路径；迁移期间的临时兼容层必须注明退出条件。
- 暂不因架构调整升级 TS/TSTL，编辑器提示与构建保持一致声明和解析语义。

## 5. 关键技术方案

### 5.1 工作区与编译

浏览器工作区拥有文本内容、二进制资源、项目设置、本地历史与同步队列。IndexedDB 起步，大资源按内容哈希管理；OPFS 为可选优化。Emscripten FS 只是运行快照副本，不是作者项目的唯一持久化存储。

产品层不做版本号管理，项目列表、保存状态、远端提示和历史记录统一使用更新时间。实现层仍保留不展示的单调修订号、请求 ID 和 baseRevision，用于并发前置条件、幂等重放及拒绝迟到结果；不能以客户端时间戳替代这些安全条件。远端较新时由用户在本机与远端之间明确选择，首版不引入实时 CRDT。缓存离线运行需要缓存 runtime、编译工具、声明与项目依赖，并提供配额提醒和导出。

编译输入为完整快照、入口、声明、配置和编译器构建；输出为 Lua、诊断、源码映射和产物哈希。编译 Worker 使用完整虚拟文件系统，不允许编译中回退到原生 read-sync。结果通过内部快照标识/buildId 关联，丢弃迟到结果；这些标识不进入产品界面。

TS 编译拆为纯核心、Monaco 集成、平台调度三层。Yue/Teal 等工具侧移植逐项验证，编辑工具不默认装入玩家 runtime。

### 5.2 RuntimeHost 与隔离

协议至少提供 loadSnapshot、start、stop、restart、suspend、releaseInput，以及状态、日志、性能事件。现有 Dora Agent 使用的试玩、截图/视觉分析及相关运行工具纳入首版适配，不另行发明新的输入回放或成功判断标准。消息携带 sessionId、runId、revision、requestId、协议版本和超时/取消信息。

先使用新容器挂载不可变产物并启动，不承诺通用热更新。资源使用现有 manifest/哈希机制并演进版本注册；使用少量验证过的公共 profile，不为脚本编辑重编译引擎。

安全隔离与响应性隔离分别验证：跨域 iframe 不保证游戏死循环不会卡住编辑器。P0 必须比较 Worker/OffscreenCanvas、适用 pthread 与 iframe 路线，并提供恶意死循环、GPU 故障和销毁恢复证据。线程构建需 COOP/COEP；单线程与线程产物按明确能力选择。

既有 Player 的主线程运行基线继续保留；Studio 对不可信创作的更高恢复要求不等于立即改写所有 Player 的主循环。最终运行拓扑由 P0 决定。

### 5.3 云后端与发布

TypeScript/Node.js 使用受支持 LTS，具体版本、HTTP 框架与存储 SDK 在实施时锁定。初期模块化单体，搭配关系数据库、对象存储与 CDN；耗时作业使用队列，必要时独立 worker 进程。初期不需要微服务。

服务内部划分身份授权、项目同步、Agent、模型配置/调度/账务、项目下载导入、发布和受限作业。资源上传受配额与类型限制，发布服务重新校验 manifest 和资源。草稿 revision 与不可变发布版本分离，发布锁定源码、编译器、引擎 build/profile、入口及哈希；提供回滚与缓存一致性。

受邀作者可以公开链接试玩；源码默认私有，必须人工开放并允许 Remix 才提供源项目 clone。源快照授权与公开运行产物分离：不能因为运行 manifest 可公开读取，就通过分享链接接口返回私有源项目。完整公共社区不作为首版前置条件。

引擎专属转换/编译工具可在隔离作业中复用已有 CLI，输入固定快照、输出固定产物，禁止长期试玩进程和任意后端 Shell。现有 Agent 的命令执行能力应按其原有语义接入项目内受控运行环境，不等同于服务器 Shell，也不能直接删掉工具。授权、事务、重试与审计新写，不原样复用本机 WebServer 的执行流程。

### 5.4 Agent 迁移

边界复评（2026-09-15）：云端编排/浏览器工具与前端 Agent/工具两条路线均需评估，尚未因近期讨论决定把全部文件工具迁到后端。游戏运行渲染始终在浏览器；共享密钥、平台流控/账务、授权与发布始终由可信后端处理。最终 Agent 与开发工具部署位置以三项关键验证为依据：完整语言构建、原 execute_command/自动试玩能力与隔离、完整会话中断恢复。局部工具移植通过不等于路线定案；保留现有实现，不先按未确定的新边界重写。

首版完全复刻现有 Dora Agent 能力，不新增、简化或重新设计 Agent 工作模式、工具语义、决策机制与自动试玩标准。以实施起点锁定的现有 Agent commit 为明确对照基线，记录完整能力清单；不得只迁移聊天/代码生成或默默隐藏难迁移工具。基线版本变化需重新对照差异。

迁移覆盖现有文件/搜索/文档/编译/命令等工具、工作模式与问题询问、会话续接、子 Agent、压缩、检查点与回滚、现有试玩/视觉分析、音乐音效生成等能力，并保持原有按供应商/配置启用能力的规则。具体完整清单从现有入口、Registry、执行器和生成链路核查，不把本文举例当作全部工具列表。Studio 的自动作者回写仅核对并保存 Agent 修改，不在任务完成后额外编译或启动试玩；构建与试玩由原 Dora Agent 自行调用 `build` 和命令/`previewGame` 等既有工具触发，浏览器宿主提供等价执行和反馈，保持原版决策节奏。

首个工具触发验证（2026-09-16）：独立 Studio Agent WASM 宿主为原 `build` 的 TS/TSX 分支提供受绑定的 `transpile-ts` 请求与结果通道。只有原工具调用才会在宿主来源启动浏览器 Worker；诊断/Lua 返回原工具，再由原 `Content.save` 写入项目。原生 Web IDE WebSocket 与 Android 构建分支不变。宿主编译资源按启动租约与登录授权供给，任务取消/超时清理工具请求。该验证不是全语言 `build` 对照，更不是 `execute_command`/`previewGame` 试玩；Lua/Yue/Teal/XML/Yarn 及真实游戏反馈仍为首版必补缺口。作者回写即便已收到同名 Lua，也不因此在工作台追加自动构建/试玩。

非渲染命令增量：原 `execute_command` 的 Lua 沙箱可以在专用宿主执行普通受限检查，但它依赖的 `Script.Dev.Entry` 在 Studio 宿主中只能是受信入口适配，不可把原 Web IDE UI 或用户游戏进程带进拥有模型和作者文件权限的 Agent WASM。`enterEntryAsync` 与 `previewGame` 必须把真实游戏执行、截图和日志导向隔离的浏览器 Player，再将受绑定结果交还原 Agent 工具；临时适配明确拒绝本宿主内启动游戏，不是首版能力复刻完成。

编排部署位置依上文边界验证决定，不预设必须云端；当前实现正在验证浏览器内原 Agent WASM 宿主、浏览器编译与试玩。AI 直接应用修改，补丁使用内部并发前置条件，自动历史记录支持恢复；不加逐补丁确认。回传原有工具所需诊断、状态及允许上传的截图，保留既有完成报告中的验证与不确定性语义。Agent 结果自动写回前端工作区，已打开文件只刷新内容、不自动切换文件；手动同步/核对控件仅在自动处理失败时作为恢复入口出现。

页面关闭或断线后保存检查点并暂停，包括关联子任务；停止派发新工具和新模型请求，取消排队/尽力取消在途调用，记账后保留可恢复状态。重新打开后从检查点继续。迟到结果通过任务/请求/快照标识隔离，不产生重复修改、调用或扣账。

平台模型调度、金额结算、账号授权与客户端暂停作为外围宿主控制，不改变 Agent 推理与工具选择逻辑。现有 Agent 的内部限额和供应商能力约束保留，与平台账户限额分别执行。

第一步共享工具契约：名称、schema、权限、错误、取消，由原生与选定的 Studio 宿主适配执行。浏览器 WASM 路线优先复用原 Lua Agent，不为迁移位置另写一套决策循环；需要 JS 目标的模块，仅在经过 JS 与 TSTL/Lua 行为对照后共享。云端路线若后续入选，再按实际需要抽取平台无关消息、计划、压缩与会话核心。

TypeScript 编写不意味着可直接运行在 Node。若双目标限制导致过度复杂，允许共享规范、测试与纯逻辑，保留必要的平台实现；不得长期靠人工同步两套同功能 Agent。

源码复用率不是能力复刻率。原生与 Studio 逐工具、逐模式、逐恢复路径做行为对照；浏览器限制形成明确阻碍并解决或由用户重新决定范围，不自动变成首版减配。完整 Agent 是 P1 出口门槛，不再后置到 P2。

#### 检查点恢复与作者回写约束（2026-09-15 核查）

原 Session.getSession 的 checkpoints 仅覆盖当前任务，不是项目全历史；原 rollbackCheckpoint 会把同一检查点 ID 的状态改为 REVERTED，而 getCheckpointDiff 仍返回该次提交的历史 before/after 内容。真实 WASM 已验证回滚删除创建文件后，历史 afterExists 仍为 true。因此恢复不得仅扫描大于已见最大 ID 的记录，也不得将历史 afterContent 直接视为当前文件。

双向回写需在项目任务停止门禁内核对当前文件快照、已确认作者基线与相关任务的检查点状态；完整项目任务索引和变更/回滚的可靠恢复记录尚需实现。内存 FileCommitEvents 只作提示，不是完整变更日志。事务提交必须以作者 revision 为前置条件；核对成功前保持 reconciliationRequired，不解除准入或声称已保存。此约束不改变 Agent 部署位置待验证的状态。

### 5.5 模型配置、共享 API 与人民币使用额度

2026-09-15 更新：用户可用量改以人民币金额呈现，取代旧版点数表达。原型暂以 CNY 为唯一展示币种；金额表示按平台费率计量的服务使用额度，不是可提现现金、充值余额或供应商账户余额。不得凭剩余额度承诺可生成的游戏数或任务数。

用户界面按以下层级呈现：

- 主数字：当前模型实际可用金额，取账号未占用余额与当前配置未占用授权额度的较小值；配置停用/授权撤销时显示不可用，不能将两层额度相加。
- 辅助数字：平台可用余额、已使用金额、暂时预留金额。预留已从可用余额排除但不计入实际消费；缺失 usage 保持待核对，不提前计为零费用或实际消费。
- 创作入口：首页与 Agent 旁显示可用金额；调用预估若存在必须注明估算范围，不能把单请求价格当作整轮 Agent/整款游戏报价。
- 模型选项突出名称、资金来源和可用状态。人民币/百万 Token 单价、三级并发和子额度约束放入可展开详情；切换不自动发生。
- BYOK：以已消耗用量为主，而非服务商余额。突出通过 Studio 发起的调用次数、已记录输入/输出 Token 和合计；按请求记录时间、项目、模型及用量状态，与平台费用账本分开。未返回 usage 标为待补记，不以零代替、不计入已知 Token 合计。正式版按请求 ID 去重，恢复同一次调用不能重复计数；失败但已发生的模型用量仍须保留。缓存、推理、音频等按供应商语义单独保留，不能把包含关系的计数再相加；非 Token 用量保留对应单位。
- BYOK 金额为次级可选信息：仅在明确单价、币种与计费口径时计算估算费用，并注明以服务商账单为准。无单价不显示虚构费用，不把平台零扣款当作服务商免费。不依赖查询服务商余额，不统计用户在 Studio 之外的 API 调用。
- 管理后台直接配置人民币使用额度及人民币输入/输出单价。供应商若以外币计费，需要明确管理员使用的换算费率、币种、版本和生效时间，不静默使用猜测汇率。

正式账务采用高精度整数最小货币单位（例如微元）或等价定点表示，累计后展示到分，避免小额调用被抹零；请求锁定费率版本，预留、结算、释放幂等。原型仅使用整数分与固定示例 Token 数，不是生产精度/计价实现。

模型同时支持平台提供和用户自带 Key。管理员在后台导入可共享 API 配置，配置包含模型服务连接信息、模型参数、人民币计价费率与并发上限；支持编辑、停用与凭据更换，秘密字段加密保存且普通列表只显示非秘密信息。

| 控制层 | 控制内容 |
| --- | --- |
| 共享 API 配置 | 允许的进行中 API 请求数、输入/输出人民币计价费率、可用状态 |
| 用户账号 | 可使用的 API、累计总金额额度、账号总 API 并发上限 |
| 用户×API 授权 | 该用户在该配置上的累计额度及并发上限，可单独调整/撤销 |

并发按正在进行的模型请求计，不按 Agent 任务计。一次调用必须同时满足 API 全局、账号总、逐 API 授权的限制；子 Agent、压缩和视觉等实际模型调用经过同一流控/账务入口，防止绕过。浏览器编译、等待试玩不占模型并发槽位。额度累计不自动按日/月重置，管理员追加或调整并保留审计记录。

用户选择获授权配置，显示模型、费率、剩余额度与排队状态。所选配置并发满时排队；不自动换模型、换配置或转用用户 Key。故障提示用户决定切换。取消、停用、撤销权限或断线后相应等待调用不得继续派发。

发起前按输入估算、该次最大输出与配置费率预留金额，派发前确认授权、可用余额和并发；调用结束按供应商实际 usage 结算，释放多余预留。账号总额与用户×API 子额度是两层约束，同一次消费各记一次，不把二者相加重复收费。金额不足不派发，不以排队绕过余额检查。

已发出但缺失 usage 的调用暂挂待核，后台可核对、补记或释放，并审计处理原因，不默认免费。失败、取消、重试、恢复按实际请求 ID 管理账务；供应商已发生的用量不能因为用户断线全部退款。费率/预留/usage/结算及人工调整留有可追踪记录，计量细节待实现前细化。

用户自带 API Key 经明确授权云端加密保存，支持跨设备使用、更换与撤销；密钥不进入试玩、Agent 上下文、日志、项目包或公开列表。BYOK 不自动消耗平台共享使用额度，也不自动成为共享 API；用户承担供应商费用，平台资源限制仍适用。BYOK 的服务地址/协议接入范围需按网络安全策略确认，不承诺任意内网端点。

现有 `/llm/list` 的本机配置返回包含 Key，不能作为云端共享配置查询接口直接复用。

### 5.6 上传、外部链接与 Studio 链接 clone

首版同时支持空白新建、描述生成、上传 `.dora` 或 ZIP 游戏包、外部开源项目链接，以及开放源码并允许 Remix 的 Studio 分享链接。统一入口识别来源，下载/授权检查后导入独立快照，不要求先使用 Git 工作流。

- 外部 Git 不限制托管商，使用通用 Git 下载路径而非仅支持 GitHub/Gitee 的白名单解析器。首版建议以公开 HTTPS Git 和 ZIP 链接为协议边界；SSH、私有仓库凭据不自动纳入范围。
- 外部复制记录来源 URL、实际提交/引用与许可证信息；ZIP 记录资源来源/校验信息。Studio clone 记录作品及源版本。项目不自动跟随上游更新。
- 公开访问不等于开源授权。保留许可证，缺失或不明确时提示，不把仓库自动标为可公开改编；不承诺自动完成法律授权判断。
- Studio 链接先检查当前源码/Remix 权限，再读取源快照；只有试玩权限时提供试玩，不能下载私有源码。
- ZIP 格式复用路径/大小/文件数/CRC/解包限制。没有当前严格 manifest 的普通游戏 ZIP 需识别项目根和入口，信息不足时提示补齐，不能仅因不符合现有 Player 严格包格式就否定上传需求。
- 导入成功与 Web 可运行分离。不兼容项目保留文件并可编辑，明确报告缺失模块、语言工具或入口；不自动替换原玩法。用户可主动要求 AI 适配，保持原始检查点。
- 链接下载在隔离作业执行，限制协议、重定向、解析后的网络目标、耗时、字节数及子资源访问；禁止私网/本机/元数据端点，不能把不限托管商变为任意 URL 代理。

通用 Git clone 下载与首版 Studio 权限控制是必交付；完整 Git UI、SSH/私仓授权和上游同步继续按需求扩展。具体引用 URL 解析与包根识别规则在导入任务中细化并测试。

## 6. 安全、数据与运维

- 编辑器与试玩独立来源，优先独立站点；试玩不得获得账号、Git 或模型凭据。
- 消息校验 origin/source/session/schema；不默认以 `*` 为目标，不接受任意执行指令。
- CSP/iframe/权限策略按最小能力配置；网络白名单，不提供任意 URL 代理，防止后端 SSRF。
- 租户级鉴权、受限上传/解包/作业，限制文件数、字节数、耗时、并发与输出。
- 工作区、预览、发布存档分别隔离；云备份与导出不能被浏览器 persist 替代。
- 记录构建/运行/发布 ID、错误类别、启动与编译耗时、流量和 AI 用量；不默认采集源码、截图或密钥。
- 关键接口覆盖限流、幂等、断线取消、重试、回滚与数据库备份恢复。
- 共享配置秘密只用于后端调用，用户只看获授权配置；管理员调整额度、停用 API、处理暂挂账务均有审计。任何子 Agent 或专用模型调用不能绕过额度控制。
- 外部 Git/ZIP 下载与用户自带模型地址均防止 SSRF；源项目权限与公开运行产物权限分别校验。

## 7. 阶段与验收门槛

阶段表示交付顺序，不是承诺工期。细项与依赖见 [进度表](PROGRESS.md)。

| 阶段 | 交付 | 出口门槛 |
| --- | --- | --- |
| D0 | 设计、工程路线、进度基线 | 最新讨论形成可追踪文档 |
| P0 | 工程基线、编译解耦、本地创作/隔离验证及 Agent 全量迁移盘点 | 无原生服务可编辑/编译/试玩/恢复；旧 IDE 回归通过；完整 Agent 适配清单明确 |
| P1 | 受邀 AI 创作首版：完整 Agent、API 管理/账务、云项目、导入/clone/Remix与快照发布 | 现有 Agent 行为对照、并发/金额/权限、断线暂停、不兼容保留及公众试玩通过 |
| P2 | 创作体验、模板教学与资源工具打磨 | 不借此后置 P1 必交付的 Agent/Remix 能力，按反馈安排 |
| P3 | 新语言体验、额外资源工具、3D/完整 Git/协作 | 按真实需求与各能力矩阵单独批准范围；完整 Agent 必需能力不在此减配 |

先抽编译核心，再建最小 Studio；不要同时重构整个 IDE、Agent 和引擎。P0 未证明运行恢复前，不以示例能跑宣布平台可靠。

CI 分别验证旧 IDE、新前端、后端、共享包与协议；对抽取模块保持编译/行为黄金测试，限制反向依赖。浏览器矩阵包含 Chrome/Edge、Firefox、Safari 与代表性 Android/iOS；真实设备不能由模拟视口替代。完整 Agent 逐能力对照；模型调用并发争用、预留/实际结算/缺 usage、子 Agent 用量、权限撤销、断线暂停与恢复需独立测试。导入测试覆盖外部不同托管商、普通 ZIP、受限网络目标、Studio 私有源码拒绝 clone 及不兼容项目保留。

指标包括首次可玩、暖运行、编译响应、发布完成率、恢复成功率与每活跃创作者成本。性能阈值基于固定设备、项目和网络实测制定；既有 Player 性能预算不是 Studio 实测成绩。
