# Studio demo 产品体验评审 · v0.4

日期：2026-09-15。对象：Studio/prototype。本轮是产品走查与交互改进，不接入真实服务，不改变“完整复刻现有 Dora Agent”的首版约束。

## 结论

v0.3 已建立 Dora Web IDE 的深灰/金黄视觉语言，但创作过程中“正在发生什么、当前是哪一个项目、当前版本能否发布”仍不清楚。v0.4 优先修正任务反馈与数据一致性，保持试玩主区、右侧 Agent 的空间结构。

## 发现与已实施改进

| 优先级 | 走查发现 | v0.4 改进与验收 |
| --- | --- | --- |
| P0 | 空白发送会使用隐藏的默认描述，并扣除演示额度 | 空输入禁用发送，快捷键也校验；不会创建调用或清空描述 |
| P0 | 新建项目立即显示已有花园，易误以为生成完成 | 首次运行前没有快照，展示空态/准备中；成功后才展示示意游戏 |
| P0 | 未运行、编译失败的草稿仍可发布 | 发布必须匹配成功运行的当前版本；失败保留旧快照，手动运行不能绕过失败演练 |
| P1 | 手机首页生成后隐藏 Agent，用户看不到进度 | 自动切换至 Agent，顶部显示阶段状态；完成后“试玩结果”回到试玩，不强制打断阅读 |
| P1 | 每次创建覆盖唯一项目，名称固定，作品页仍写月光花园 | 根据描述生成可改名称；最近项目在本次会话中保存独立代码、对话、检查点、分享设置与草稿输入，可切回 |
| P1 | 排队恢复使用通用描述，空输入与失败操作容易造成意图丢失 | 排队保留原请求，退出排队将其返回输入框；额度/授权失败保留输入；独立暂停创作与试玩停止 |
| P1 | Remix 并未复制代码，分享链接不能识别具体项目 | 对本次会话中的 Studio 链接查找项目及开放授权；复制已发布代码快照，保持新项目私有，不混入未发布草稿 |
| P1 | 长对话不断撑高整页，输入框与试玩分离 | Agent 消息区域独立滚动、输入区固定在侧栏内；新消息滚至末尾，桌面和手机均限制侧栏高度 |
| P2 | 首页模型标签不同步、复制按钮未复制、保存状态误导 | 标签同步所选配置；复制演示链接，失败选中供手动复制；统一“本次会话，刷新后清空” |
| P2 | 经常使用的文本过小、首次操作含义不明确 | 增大对话和关键状态文字；“新建并生成”明确创建新项目，增加发送快捷键提示 |

## 验证方式

- 在浏览器中实际操作：描述生成、空消息、重命名、草稿编辑、发布拦截、私有拒绝 clone、授权后复制、公开链接 Remix、原项目草稿切回。
- 实际操作排队退出/恢复、主动暂停、断线恢复、额度不足、编译失败、暂挂账务和 BYOK；确认输入保留及共享额度边界。
- 扩展 test.cjs：独立项目、空态、重命名、未运行发布拦截、复制已发布代码、原稿保留和主动暂停；保留既有 ZIP、通用 Git、错误状态与响应式回归。
- 桌面、手机渲染与宽度检查；不把浏览器模拟尺寸当作真实手机设备验收。

## 明确不在本轮实现的能力

- 所有项目、点数、发布状态均在页面内存；刷新会清空，不声称已保存到本机或云端。正式存储及离线恢复仍按主设计实现。
- 所有 prompt 仍播放同一套模拟流程与花园 Canvas，不调用模型、不执行编辑代码、不读取上传包内容、不下载仓库。
- 分享链接仍是 example.invalid；没有真实公开发布、真实授权服务或真实账务。复制演示链接是本机剪贴板操作。
- 四个演示阶段不定义或削减真实 Dora Agent 的工具、策略和能力。

当前状态：本轮交互改进完成后交付用户评审；最终视觉喜好、真实生成质量、云服务可用性仍需要后续验收。
