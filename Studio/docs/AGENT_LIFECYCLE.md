# 浏览器 Agent 宿主停止与恢复约束

状态：源码核查后的实施约束，尚未实现完整暂停/恢复。2026-09-15。

## 已确认的现有语义

- `Assets/Script/Lib/Agent/Session.ts` 的 `stopSessionTask` 只设置指定任务的 `activeStopTokens`，返回 `stopping: true`；原实现明确等待 runner 的 `task_finished` 才持久化 STOPPED、移除旧 token 并允许续接。不能将请求成功作为停止完成。
- `startPromptTask` 为每个任务创建独立 StopToken，不能假定停止主会话会停止全部子会话。
- `stopSessionTask` 在任务 finalizing 时拒绝停止，必须等收尾完成，不能强改数据库状态或直接释放执行环境。
- `listRunningSessions` 提供当前运行会话，但调用方必须按可信根会话及项目约束筛选，不能误停另一个项目。仅一次列表快照不足以排除正在产生的新子任务。
- `installAgentWasmHost.close()` 仅释放 JS 回调和通信，不代表保存。Lua 桥接现在提供 snapshot/quiesce 固定操作；quiesce 通过原 Session 门禁与停止观察返回活动任务列表，不能把一次请求返回当成全部任务终止。

## 当前已实现边界

- `beginProjectTaskQuiescence` 按原会话的规范项目路径关闭新任务准入，覆盖主任务、子任务创建与续接入口；轮询同项目的活动任务，finalizing 等待收尾，其他活动任务请求原停止机制。
- `persistStoppedAgent` 等待 quiescent 且 pending 为空，再通过 `doraSyncUserStorage({afterCurrent:true})` 确认本机 IDBFS 写入屏障。失败不释放 Lua 准入门禁；网络断开和存储失败不等于允许新任务继续运行。
- `mountAgentHostFrame.persistAndClose` 等待上述宿主持久化确认后才销毁 iframe；失败保留宿主，并发调用共用同一个操作。显式 close 是强制清理，不能用它替代正常保存关闭。
- Chrome 真实 WASM 已验证活动主/子任务从 pending 走到 STOPPED、同步后新实例读回会话与用户消息、读回不重发模型请求，以及隐藏 iframe 创建/连接/保存/销毁。测试不覆盖浏览器强杀时最后一次写入，也不证明云端账务去重。

## 正式工作台接入前仍缺少的连接

正式 App 当前仍显示未连接的 AgentPanel，不能仅把一个测试宿主 URL 传给它就开放创作：

1. 提供可信宿主启动产物：创建或读取正确项目的 Agent 会话，建立稳定存储命名空间，再发 ready；当前真实测试的初始化 Lua、固定会话及本地模型服务不是产品配置。
2. 绑定作者工作区与工具：Agent 不能写一份无人读取的 WASM 项目副本；所有修改须回到当前项目 revision/检查点事务，再驱动编译和隔离试玩。
3. 绑定平台模型授权与用量：不能将共享密钥装进静态宿主产物；中断后的请求关联与结算须有可信后端证据。
4. 在 open/create/另存副本/恢复检查点/导入等项目切换路径统一协调保存；保存失败时保留当前项目与宿主，不先激活下一个项目再等待旧实例保存。

Agent 本机保存成功与作者项目保存成功是两个不同的确认，尚未实现跨两者的恢复协议。正式 UI 不得将前者显示为整个项目已安全保存或已同步云端。

## 必须实施的关闭顺序

1. 宿主进入 quiescing：禁止新 prompt、续接、问答触发的新任务和子任务创建；保留停止/状态读取及已有任务收尾能力。该门禁属于 Studio 宿主控制，不改变原 Agent 决策。
2. 识别绑定项目/根会话的全部活动任务，对每个任务调用原停止能力。记录 taskId，不能只记录 sessionId；finalizing 任务等待完成。
3. 持续观察原任务终态，重新确认没有新增活动任务及未完成工具副作用。等待超时只能报告未完成，不返回“已暂停”。
4. 完成项目修改、检查点、Agent 会话数据库和文件的持久化屏障。运行内存中的数据库更新不等于浏览器持久存储已确认。
5. 记录模型请求关联 ID 与恢复游标。未确定的模型结果保持 pending，恢复时查询，不自动重发或重新计费。
6. 只有上述步骤完成后才报告可恢复暂停，随后关闭传输并释放 WASM。恢复创建新宿主 generation，加载已确认状态后按原续接语义继续。

## 页面突然消失

pagehide 只能触发尽力清理，不能作为等待异步停止/保存的可靠屏障。因此持久化必须发生在任务运行期间的重要边界，而不是只在离开页面时做。强制终止后只能从最后确认状态恢复，并与后端请求账本对账；不宣称最后一帧修改必定保存。

## 交付验证要求

- 同根主任务和多个子任务在模型请求、文件修改、试玩期间分别停止；其他项目不受影响。
- 停止与新子任务创建竞态、finalizing、重复停止、超时、晚到事件。
- 检查点/项目/会话持久化失败时不得报告暂停完成。
- 强制关闭页面再打开：没有重复工具修改、重复模型请求或重复扣费。
- 正常关闭与浏览器强制回收分别验证；测试通过不替代人工验收。

在上述门禁和持久化屏障落地前，禁止把传输 close 命名或显示为“已保存并暂停 Agent”。
