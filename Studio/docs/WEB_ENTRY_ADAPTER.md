# Web Entry 宿主适配验收约束

状态：实验性宿主适配已实现，基础命令及启动/停止探针通过；未用于正式生产打包，完整验收未通过。2026-09-15。

## 已确认的失败

`STUDIO_TEST_COMMAND_EXECUTE=1` 最初在加载 `Script.Dev.Entry` 时被拒绝。添加 `packages/runtime-web/Entry.lua` 后，真实 Web Lua 调用原 `Agent.Tool.Command.executeCommand` 已可执行 `print(6 * 7)`，启动/停止同一入口两次并验证运行编号和空闲状态。最新证据为 `apps/web/artifacts/runtime-host-command-module-execute/result.json`。此基础探针不代表完整命令能力通过。

## 原接口不可省略的语义

来源：`Assets/Script/Dev/Entry.yue`、`Assets/Script/Lib/Agent/Tool/EntryLease.ts` 与 `CommandPreview.ts`。

| 接口 | Web 适配必须保持的约束 |
| --- | --- |
| getCurrentEntryStatus | 区分空闲与运行；保留数字 runId，以及当前入口路径、工作目录、项目根和运行种类 |
| enterEntryAsync | 调用入口同步将 runId 恰好增加一次，之后才允许异步等待；加载项目模块，执行函数型模块返回值；返回实际启动结果而非提交成功 |
| stop | 空闲返回 false；运行中清理场景并转为空闲；不得停止不属于调用者的运行 |
| allClear | 清除项目场景、项目模块缓存和项目状态；恢复搜索路径与投影等全局设置；保留宿主控制通道和必要系统 UI |

EntryLease 在启动前预测 `current runId + 1`，不能直接用 RuntimeHost 的字符串 runId 替换；需明确两个编号的映射。原 previewGame 的顺序是获取租约、allClear、beginGameCapture、记录预测编号、启动入口、采样、释放捕获与租约，不得改成先运行再补采样基线。

原 allClear 还清理 Entity、Platformer、Audio、Struct、编译缓存及 Wasm 状态，并筛选 Routine 与系统节点。不可直接复制整段原生入口：其中包含桌面开发 UI 和宿主事件重建，也不可只调用 Director.cleanup 后宣称等价。需逐项确定 Web 中的所有者，防止清掉 Agent 自己的调度协程或通信桥。

## 实现边界

- 保持原 Command、CommandPreview 和 EntryLease 的行为；适配放在受信任宿主层，不由上传项目提供同名模块。
- 用户模块与宿主模块分离解析，项目文件不可覆盖宿主入口或 Agent 实现。
- 执行取消、异常与清理必须可由宿主观测；卡死时的终止手段不能只依赖已卡死的 Lua 线程。
- 现有浏览器测试将 Agent 模块注入测试快照，仅用于定位依赖，不是生产打包或安全隔离方案。
- Lua 路径通过不代表 Git 路径通过，两条路径单独验证。

此矩阵通过后仍需完整 Agent 会话、子任务、模型计量与中断恢复验收；不替代产品的人工验收。

当前适配用启动前的模块和 Routine 集合作为宿主基线，只适用于独占测试宿主；尚未证明运行期间新增宿主模块/协程的所有权隔离，也未实现原 allClear 的完整 userdata 清理、编译缓存及 Wasm 清理。因此不能宣称与原入口完全等价。可信预载、防项目覆盖、故障硬终止及完整清理是进入正式产品前的必要工作。
