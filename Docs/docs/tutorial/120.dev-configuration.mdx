## 2. Build Game Engine Runtime

Install the latest stable xmake and the native platform tools: Xcode for macOS/iOS, Visual Studio C++ tools for Windows, a compiler and SDL system development libraries for Linux, or Android Studio/SDK and JDK 17 for Android. On Windows ARM64, install the native ARM64 xmake distribution, not an emulated x64 build, so managed host tools resolve to the correct architecture. xmake manages Go, Rust/rustup and Emscripten; no separate dependency build scripts are required. Linux system packages are listed in `.github/workflows/linux.yml`.

Run from the repository root:

```sh
xmake dora-build --platform=macosx --mode=debug
xmake dora-build --platform=linux --mode=debug
xmake dora-build --platform=windows --arch=x86 --mode=debug
xmake dora-run
xmake dora-package --platform=ios --appledev=simulator --mode=debug
xmake dora-package --platform=android --mode=debug
xmake dora-web
```

Run only the command for the intended platform. Build implementation lives in `Projects/xmake/`, with `xmake.lua` as the root entry. Desktop output is `build/<platform>/<arch>/<mode>/Dora` (`Dora.exe` on Windows; `Dora.app` on macOS). Existing `build_*`/`run_*` scripts are compatibility dispatchers; run commands use repository Assets and do not forcibly terminate other Dora processes.

Windows x86 also needs a 32-bit MinGW GCC for Wa's Go cgo runtime. Put `i686-w64-mingw32-gcc`/the MSYS2 MINGW32 `gcc` on PATH, or set `CC` to its executable. Rust output is placed on a local disk (`LOCALAPPDATA`, or a custom `CARGO_TARGET_DIR`) even when the repository is on a shared drive.

### IDE projects

```sh
xmake dora-ide --platform=macosx
xmake dora-ide --platform=ios --appledev=simulator
xmake dora-ide --platform=windows --arch=x86
xmake dora-ide --platform=linux --kind=compile_commands
```

Generated projects live under ignored `build/ide/<platform>/<native|simulator|device>/<arch>/`; do not commit or hand-maintain them. Windows uses vsxmake, Apple uses the Xcode generator, and Linux can use compile_commands. Android Studio still opens `Projects/Android/Dora`: Gradle/NDK CMake compiles C/C++, with the build graph exported from xmake.

### Mobile and Web

Android pins NDK `26.1.10909125` and CMake `3.22.1`. Default ad-hoc iOS device packages are not installable/distributable; see `Projects/xmake/ios/README.md` for signing. See `Projects/xmake/web/README.md` for core/preset/custom, feature overrides and pthreads. Node.js/pnpm are still used for frontend tooling and JS tests; Emscripten bootstrap requires host Python.

## 3. Build Web IDE

1. Compile and run the Dora SSR engine.

2. Install the latest version of [Node.js](https://nodejs.org/) and [pnpm](https://pnpm.io/installation).

3. Initialize the Dora Dora editor. Use `pnpm start` for development.

	When you need the engine runtime to serve the updated Web IDE, run `pnpm build`. It creates the production Web IDE static files and syncs them to `Assets/www`.

## 4. Unified Build Flow

All entries use one xmake graph: dependency checks/installation → incremental Lua bindings and runtimes → vendor/engine compilation → platform packaging. `dora-run` builds and launches, `dora-ide` generates disposable IDE projects, and `dora-package` creates distribution packages. Do not maintain separate prebuilt-library or manual-project source lists.
