# Run Love2D Projects in Dora SSR

Dora SSR can host Love2D 11.5-style projects as scene nodes. Each `LoveNode`
owns an isolated Lua 5.5 state, virtual window surface, event queue, physics
world, and audio bus. The node is rendered into Dora's scene graph, so a Dora
project can place, scale, hide, restart, or run several Love projects without
giving any of them control of the application window or main loop.

This is source and API compatibility for Love projects. It is not LuaJIT ABI
compatibility and it does not embed SDL's application loop.

## Create a LoveNode

Put the Love project under a Dora content search path. A minimal project can use
the normal Love callbacks:

```lua title="LoveGame/main.lua"
local love = require("love")

function love.load()
	message = "Hello from an isolated Love state"
end

function love.update(dt)
	-- Update this Love instance.
end

function love.draw()
	love.graphics.clear(0.05, 0.08, 0.12, 1)
	love.graphics.print(message, 24, 24)
end
```

Create the node from a normal Dora program:

```lua title="Script/init.lua"
local _ENV = Dora

local game = LoveNode("LoveGame/main.lua")
if game then
	game.position = game.position + Vec2(80, 40)
	game.scaleX = 0.75
	game.scaleY = 0.75
	game:addTo(Director.entry)
end
```

`conf.lua`, `main.lua`, and project modules are resolved relative to the Love
source root. A `.love` ZIP package can also be used as a source. Reads, writes,
mounts, module loading, and package staging all go through Dora's `Content`
system; the isolated state cannot use native Lua modules or bypass the content
policy with host filesystem paths.

`game:restart()` closes the old state and all instance-owned resources before
booting a new state. An error or ordinary `love.event.quit()` stops only that
node. `love.event.quit("restart")` performs the same full restart on the current
LoveNode after `love.quit()` returns; returning a truthy value cancels it.

## Editor and language support

Love definitions are opt-in and use the existing Dora compilation pipeline:

- Lua, Teal, and YueScript: `local love = require("love")`
- TypeScript and TSX: `import "love"`

There is no file comment, project profile, special TSX transform, or default
`love` declaration in ordinary Dora files. This lets one project mix Dora and
Love sources without polluting the other files' globals. TypeScript, Teal, and
YueScript errors are mapped back to their original source locations.

The declaration files shipped with the current engine are the authoritative
list of callable functions and object methods. The table below describes the
broader module boundary.

## Compatibility status

Status meanings:

- **Supported**: the documented embedded subset is implemented and covered by
  automated and platform runtime tests.
- **Partial**: commonly used APIs are available, but the listed Love module is
  not complete.
- **Deferred**: intentionally outside the first embedded runtime.

## Lua compatibility boundary

Love states run Lua 5.5. Source code, current Lua 5.5 bytecode, `unpack`,
`loadstring`, `package.loaders`, and the 32-bit `bit` compatibility module are
supported. `getfenv` and `setfenv` have limited source compatibility for Lua
functions and positive stack levels. `getfenv(0)` returns the isolated state's
global table, while replacing a Lua 5.1-style thread environment with
`setfenv(0, env)` is not supported by Lua 5.5 and produces a targeted error.
LuaJIT `ffi`, `jit`, LuaJIT/Lua 5.1 bytecode, and Lua 5.1 ABI native modules are
also rejected with targeted diagnostics. Supply source code or compile bytecode
with the Lua 5.5 version shipped by Dora.

## Current platform evidence

macOS has the complete build-and-runtime evidence for the implemented subset,
including Metal pixel tests, SoLoud audio, PlayRho physics, multi-instance
isolation, reload, and sanitizer runs. iOS Simulator has target-build and live
Metal evidence for Canvas readback, multi-instance isolation, basic SoLoud
source lifecycle, the 13-scene advanced graphics matrix, and the full current
PlayRho physics scene. Android has a three-ABI packaged build and Android 14 /
API 34 AVD runtime evidence for two LoveNode instances, the same advanced
OpenGL ES graphics and physics matrices, system-injected single and multi-touch,
keyboard events, and explicit IME focus/text routing.

Linux ARM64 is built from the current source and starts through Dora's normal
`Script.Dev.Entry` under Ubuntu 26.04. Its Mesa llvmpipe OpenGL ES 3.0 run passes
the complete Mouse/Cursor workflow, RGBA8/MSAA Canvas readback, PlayRho physics,
the 13-scene advanced graphics matrix, two isolated LoveNode instances, two
native Thread generations across restart, and Ogg/Theora VideoNode pixels read
back from a RenderTarget. This headless run uses Xvfb and SDL's dummy audio
driver, so it does not prove physical input, a real display driver, or audible
output. Windows has project-manifest coverage plus a Zig x86 compile/link gate
that produces four PE32 Runtime, PlayRho, and SoLoud test executables; native
MSVC execution, the full Dora target, and renderer behavior are still pending.
Mobile physical I/O, microphone, haptics, cross-app audio behavior,
and audible output also remain release-validation items. Do not interpret a
module marked Supported above as a completed release-platform matrix until the
target platform is listed as supported by the corresponding Dora release.
