# Dora Agent 游戏画面检查

在 Agent 的现有模型配置中使用已支持的官方 DeepSeek 服务或国内 GLM Coding Plan 服务，即可使用默认视觉能力，无需新增视觉模型配置。

可以直接提出：

> 运行当前游戏，检查开场画面的角色、HUD、平台和文字是否清楚，有没有裁切或遮挡。结合源码调整确实存在的问题，修改后重新截图对比。

代码模式下，Agent 可在 `execute_command` 的 Lua 沙箱中调用 `previewGame()`，启动入口、取得 1—3 张游戏画面并结束此次预览；Remix 可以保持可见。入口可写项目中的 `.lua`、`.ts`、`.tsx`、`.yue`、`.tl` 或 `.xml` 文件，也可省略扩展名；工具统一运行构建后的 Lua 文件。`captureAtSeconds` 必须包含 1—3 个严格递增的时间，且每个值都在 0—10 秒。`analyze_image` 读取这些图片并返回文字观察。主 Agent 结合源码中的布局、相机和坐标决定改动，再按需构建、取景对比。计划模式只能分析已有图片，不启动游戏。

`previewGame()` 的每次结果都会自动进入命令输出，并作为 `execute_command.previewGame` 返回。即使测试脚本没有主动打印 `result.message`，参数、构建入口或捕获失败也会使外层 `execute_command` 失败并直接给出原因，避免 Agent 猜测后重复调用。

Web IDE 和 Remix 的工具步骤显示图片、实际视觉模型与分析报告；点击缩略图可放大。压缩摘要会保留看图目的和有界的文字结论，省略图片路径等元数据；需要确认当前画面时重新取景。图片被删除或损坏时会明确失败或显示缺失占位。

首版默认路由：

| 当前 Agent 服务 | 看图模型 |
| --- | --- |
| 官方 DeepSeek | `deepseek-v4-flash-vision-exp` |
| 国内 GLM Coding Plan | `glm-4.6v` |

未知服务或自定义网关不自动启用看图，也不会切换到其他供应商。GLM 的实际 API 请求已验证，尚未核查其账单是否计入 Coding Plan 套餐额度。

模型负责定性观察，不负责精确像素测量。单次分析先回答主要检查重点，也会报告画面中最多五个明显的额外问题、严重度、置信度、前后变化和静态图无法验证的事项。额外发现不会自动扩大修改范围。单张图不能证明移动、碰撞或输入正确；文字识别和遮挡判断也可能出错，主 Agent 应核对源码并按需复拍。

只有用户明确要求视觉检查，或可见结果无法通过源码和确定性运行测试验收时才取景。普通任务通常最多检查一次；明确视觉任务通常使用基线与最终对比两轮。每任务硬限制 3 个取景批次、6 帧和 3 次实际分析请求，第三轮留给失败重试或高置信阻断问题；已报告累计用量达到 60000 token 后不再发新请求。单张图片仍限制为 4 MiB，视觉请求长边默认 1280。这些是工程限额，不是图片质量评分或精确费用承诺。

本轮已验证 macOS 本地引擎、Web IDE 和 Remix。移动真机按用户要求延期，其他平台尚未验证。详细结果见 [评测](./EVALUATION.md) 与 [验收审计](./ACCEPTANCE-AUDIT.md)。
