# Dora Agent 多轮游戏创作与视觉调用验收（2026-09-07）

## 结论

本轮以真实用户方式在独立项目中连续发送五轮需求，最终生成并清理完成单文件街机游戏《星港折跃》。视觉调用行为判定为 **基本符合预期，可以通过本轮验收，但仍有两项收敛空间**。

- 非视觉原型轮明确要求不截图，Agent 没有调用图片工具；最终产品清理轮也保持 0 次取景、0 次分析。
- 视觉迭代轮共成功取景 3 个批次、5 帧，调用 2 次 `analyze_image`，低于每任务 3 批次、6 帧、3 次分析的硬限制。
- 调用顺序是“标题与玩法基线 → 一次综合分析 → 一次集中修改 → 标题/玩法/失败三态复查 → 结束”，没有出现每次编辑后重新构建和截图的循环。
- 首份报告同时回答主要任务并扫描额外问题，准确发现标题装饰环压字、提示对比度弱、实体与连击信息不够突出；主 Agent 阅读源码后统一调整，最终图能看到改善。
- 第二份报告能对比前后状态，并明确暂停、难度递增等动态行为无法由静态图确认；但把画面上沿正在进入场景的星门当成“裁切”，以及由单帧得分 0 推测计分风险，说明静态视觉仍会产生误报。
- 视觉预算只统计成功进入取景管线的调用。本轮在第一次成功分析前还有 3 次 `previewGame` 参数失败：三次都包含超过工具上限的 11.5 秒取景点，其中一次又读取了不存在的结果标记文件。第一次调用没有打印 `result.message`，Agent 错误猜测为入口名问题，随后重复了相同非法时间参数。另有 1 次普通运行诊断。这些调用没有消耗取景预算，但从用户体感看仍属于工具折腾。

因此，当前优化已经解决“改一点就截图一次”的主要性能问题。下一步更值得修的是失败取景尝试的总次数，以及多帧报告对动态状态和入场边界的判断规则，而不是继续压缩单次图片问题。

- 初始标题图：装饰环确实穿过副标题/提示区域，底部提示偏暗；首次报告判断准确。

## 游戏质量检查

最终版本包含标题页、左右/A/D 移动、晶体收集、两类无人机、星门、得分、生命、连击倍率与衰减、粒子和浮动得分、受伤闪烁/震屏、P/Escape 暂停、游戏结束及 R/Enter 重开。流速、晶体和无人机生成间隔会随距离提升难度。

最终一轮构建报告为 1/1 文件通过。无截图运行冒烟确认入口可从标题态持续运行并干净停止。此前自动演示实际到达得分 100 和失败态，提供了玩法推进、碰撞和结束状态的运行证据。持续方向键操作和暂停切换没有在本轮单独做真实键盘验收，因此不扩展为完整交互认证。

## 改进建议

1. 给“意图执行 `previewGame` 的命令”增加较小的尝试预算，或在相同错误签名重复时直接停止。当前预算只覆盖实际捕获，无法约束参数/文件错误导致的重试。
2. 在多帧分析提示中要求先区分“对象正在从出生边界进入”与真实裁切，再把单帧缺失的动态现象列为待验证项。得分、连击衰减、暂停和难度变化不能由一帧直接判错。
3. 避免为了截图给成品加入自动演示钩子。若必须构造多状态，应使用一次性的受控验收夹具，并在同一任务结束前删除。本轮依靠追加清理轮才移除了这些代码。
4. 将主模型长输出单独治理。GLM 的输出上限重试和 DeepSeek 的超长编辑参数是本轮最大等待来源，与两次约数秒级视觉请求无关。
