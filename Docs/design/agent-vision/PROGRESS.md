## 1. 当前状态

**核心功能已实现，DeepSeek 与 GLM 国内 Coding Plan 均完成真实 Dora Agent 视觉工具闭环；首版本地验收已完成。** 首版固定视觉模型分别为 `deepseek-v4-flash-vision-exp` 和 `glm-4.6v`，复用同服务配置，不新增视觉配置或切换。GLM 请求成功不证明套餐账单归属。

三个真实游戏的无视觉开发与视觉复查均已完成。G02 的开场平台/金币布局经观察、代码修改、复拍和独立原图核对得到改善；G01 未发现需改问题；G03 暴露坐标、遮挡与 OCR 误判，保留失败证据。G03 重启和真实上下文压缩后复用旧图通过。

已完成 macOS 原生构建、脚本编译、前端生产构建，资产归属/清理/配额、HTTP 失败与取消/超时、持久化预算、GPU 取消、用户接管和工具并发回归。正式构建连续 40 次捕获后资源计数稳定。真实 Remix 图片放大交互通过；Web 真实会话的显示、放大/关闭、缺失占位和文件恢复已通过。

最终证据见 [验收审计](./ACCEPTANCE-AUDIT.md)。计划模式、XML 模式、原生 childrenVisible、G02 独立模拟输入路线及相机动态验证、systemUI 排序、窗口最小化/恢复均有通过记录。**移动真机由用户明确延期，不计入本轮门槛。** 持续 OS 方向键未验证，不能将模拟输入或 CUA 短按当成其证据；不影响本次视觉工具与三个游戏评测完成的结论。

用户补充：视觉模型只做定性观察，主 Agent 结合源码决定精确调整；不要求模型像素坐标准确。文件大小仅作工程限额，不据此评价视觉质量或推算费用。

2026-09-07 完成视觉调用收敛优化：普通任务通常最多一次检查，明确视觉任务通常为基线与最终对比两轮；每任务硬限制 3 个取景批次、6 帧和 3 次实际分析请求。单次报告会在主要问题之外扫描明显额外问题，但不自动扩大任务。视觉请求仅带最多 6000 字符的当前任务摘要；压缩输入保留看图目的和有界文字结论，删除图片路径、尺寸与 usage 等元数据，使后续修改仍保有原因。23 项压缩/请求契约与 6 项真实取景预算检查通过，见 `vision-loop-contract-result.json`、`vision-compression-contract-result.json`、`vision-capture-budget-result.json`。

同日新增真实多轮创作验收：会话 216 最终完成《星港折跃》，视觉任务实际使用 3 个取景批次、5 帧和 2 次 DeepSeek 分析；顺序为基线、集中修复、最终三态复查，非视觉轮均为 0 次视觉调用。人工核对确认首次报告能发现压字、对比度和实体层级问题，最终报告也出现一次出生边界裁切误判和由静态得分帧引出的动态风险误判。结论为基本符合预期，失败取景尝试尚未受预算约束。详见 [多轮创作验收](./LIVE-ACCEPTANCE-2026-09-07.md)。

纯 DeepSeek 对照会话 217 完成《引力花园》：核心开发和最终核对轮没有视觉调用，视觉轮用 2 个批次、4 帧和 2 次分析完成基线、集中实现及三态终验，4531 个视觉 token。临时状态在同一任务中清理。人工核对认为主要布局和层次观察准确，但保留暗色星云风格误判及无依据的分辨率质疑；成功取景前有 2 次把 `init.ts` 误作 Lua 入口的参数失败，另一次普通路径诊断失败不计作取景。详见 [纯 DeepSeek 复验](./DEEPSEEK-LIVE-ACCEPTANCE-2026-09-07.md)。
